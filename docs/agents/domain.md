# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring a code area, read the root glossary and relevant ADRs if they exist. Proceed silently if they do not. The domain-modeling skill creates them when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests. If a needed concept is missing, reconsider the term or note the gap for domain modeling.

If work conflicts with an ADR, identify the ADR and explain the conflict.
